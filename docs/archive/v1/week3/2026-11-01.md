   - 없는 id 수정 → 404
   - 검증 실패 수정 → 400

2. Route Handler (`src/app/api/subscriptions/[id]/route.ts`)
```ts
import { NextResponse } from 'next/server';
import { subscriptionInputSchema } from '@/lib/subscriptions/schema';
import { subscriptionRepository } from '@/lib/subscriptions';

type Ctx = { params: Promise<{ id: string }> };

export async function PUT(request: Request, { params }: Ctx) {
  const { id } = await params;
  const parsed = subscriptionInputSchema.safeParse(await request.json().catch(() => null));
  if (!parsed.success) {
    return NextResponse.json({ error: { code: 'VALIDATION_ERROR', message: '입력값을 확인해 주세요' } }, { status: 400 });
  }
  const updated = await subscriptionRepository.update(id, parsed.data);
  if (!updated) {
    return NextResponse.json({ error: { code: 'NOT_FOUND', message: '항목을 찾을 수 없습니다' } }, { status: 404 });
  }
  return NextResponse.json(updated);
}

export async function DELETE(_request: Request, { params }: Ctx) {
  const { id } = await params;
  const removed = await subscriptionRepository.remove(id);
  if (!removed) {
    return NextResponse.json({ error: { code: 'NOT_FOUND', message: '항목을 찾을 수 없습니다' } }, { status: 404 });
  }
  return new NextResponse(null, { status: 204 });
}
```
> Next.js 버전에 따라 `params`가 Promise인지 확인한다. 최신 App Router는 `await params`가 필요하다.

## 기본기 노트 (30분): HTTP 캐싱과 CORS

**Cache-Control**
- `no-store`: 저장하지 않음. 민감하거나 매번 최신이어야 하는 응답 (예: 구독 목록)
- `no-cache`: 저장은 하되, 사용 전에 서버에 검증 요청
- `max-age=N`: N초 동안 서버 요청 없이 사용

**ETag**: 리소스 버전 지문. 클라이언트가 `If-None-Match`로 보내면 변경이 없을 때 서버가 `304`를 응답한다.

**CORS**: 브라우저가 다른 출처(origin)의 응답을 읽을 수 있는지 정하는 규칙. 같은 origin의 Next.js API에서는 보통 설정이 필요 없다. 외부 도메인에서 호출할 때 `Access-Control-Allow-Origin`을 설정한다.
