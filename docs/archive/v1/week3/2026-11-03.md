# 11/03 (화) · 3주차 6일 — 접근성 자동 검사 (axe)

**유형**: 구현 | **시간**: 2시간

## 오늘의 목표
목록·폼 페이지에 axe 자동 검사를 붙이고, 발견된 위반을 고친다.

## 구현 (100분)

1. 설치
```bash
pnpm add -D @axe-core/playwright
```

2. 테스트 (`e2e/a11y.spec.ts`)
```ts
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

const pages = [
  { name: '목록', path: '/' },
  { name: '등록 폼', path: '/new' },
];

for (const p of pages) {
  test(`${p.name} 페이지 WCAG 2.1 AA 위반 없음`, async ({ page }) => {
    await page.goto(p.path);
    const results = await new AxeBuilder({ page })
      .withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa'])
      .analyze();
    expect(results.violations).toEqual([]);
  });
}
```
> `/new` 경로가 없으면 등록 폼이 있는 페이지 경로로 바꾼다.

3. 위반이 나오면 `results.violations`의 `id`, `impact`, `nodes`를 확인하고 수정
   - 자주 나오는 항목: 라벨 누락(`label`), 대비 부족(`color-contrast`), 제목 순서(`heading-order`), 버튼 이름 없음(`button-name`)

4. 수정할 수 없는 항목은 예외 사유와 함께 기록하고, 필요한 경우에만 `.disableRules(['규칙id'])`로 제외 (사유를 주석으로 남김)

5. 위반 0건 확인 후 커밋: `test: axe 기반 접근성 검사 추가`

## 학습 포인트
- axe는 자동 검사로 잡을 수 있는 약 30~40%의 문제만 찾는다. 키보드 흐름과 읽기 순서는 수동 확인이 필요하다
- 위반 결과의 `impact`(critical, serious, moderate, minor)로 우선순위를 정한다
