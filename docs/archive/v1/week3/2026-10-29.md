# 10/29 (목) · 3주차 1일 — GitHub Actions 초안

**유형**: 구현 | **시간**: 2시간

## 오늘의 목표
PR이 열리면 설치, 린트가 자동으로 실행되는 워크플로우를 만든다.

## 구현 (100분)

1. `package.json`에 패키지 매니저 버전 고정 (pnpm/action-setup이 이 값을 읽는다)
```json
{ "packageManager": "pnpm@9.15.0" }
```
> 로컬에서 `pnpm -v`로 확인한 버전을 그대로 쓴다.

2. `.github/workflows/ci.yml`
```yaml
name: CI

on:
  pull_request:
  push:
    branches: [main]

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - run: pnpm lint
```

3. 테스트용 브랜치 생성 후 PR 열기
```bash
git checkout -b ci/setup
git add .github
git commit -m "ci: GitHub Actions 워크플로우 초안 추가"
git push -u origin ci/setup
```

4. PR 화면에서 Actions 탭 확인

5. 커밋 메시지: `ci: 린트 단계가 포함된 워크플로우 추가`

## 학습 포인트
- `--frozen-lockfile`: lockfile과 package.json이 다르면 실패시킨다. CI에서 의존성이 몰래 바뀌는 것을 막는다
- `cache: pnpm`: 설치 시간을 줄인다
- `on: pull_request`와 `on: push`를 분리해서 PR 검증과 main 검증을 둘 다 건다

## 완료 체크리스트
- [ ] PR 생성 시 워크플로우가 자동 실행됨
- [ ] lint 단계가 초록불
- [ ] `packageManager` 필드 추가 및 커밋

## 막히면 확인할 것
- `Multiple versions of pnpm specified` 에러: `packageManager` 값과 `pnpm/action-setup` 설정 중복 여부 확인
- `ERR_PNPM_OUTDATED_LOCKFILE`: 로컬에서 `pnpm install` 후 lockfile을 커밋
