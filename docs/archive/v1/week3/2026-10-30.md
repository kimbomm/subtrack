# 10/30 (금) · 3주차 2일 — 타입체크, 테스트, 커버리지 게이트

**유형**: 구현 | **시간**: 2시간

## 오늘의 목표
CI에 타입체크, 테스트(커버리지 포함), 빌드를 추가하고, 커버리지 임계값이 실제로 CI를 막는지 확인한다.

## 구현 (100분)

1. 워크플로우에 단계 추가 (`ci.yml`의 `steps` 아래에 이어서)
```yaml
      - run: pnpm typecheck

      - run: pnpm test:coverage

      - run: pnpm build
```

2. 커밋 후 push, Actions에서 모든 단계가 초록인지 확인

3. **게이트 검증 실험** (필수)
   - 브랜치 `ci/gate-test`에서 `vitest.config.ts`의 임계값을 `100`으로 올린다
   - 커버리지가 100%가 아니므로 CI가 빨간불이 되는지 확인
   - 스크린샷을 저장한 뒤 임계값을 90으로 되돌리고 커밋

```bash
git checkout -b ci/gate-test
# vitest.config.ts 임계값을 100으로 수정 → commit → push → CI 실패 확인
# 스크린샷 저장 → 90으로 되돌림 → commit → push
```

4. 실험 결과를 `docs/ci-gate-experiment.md`에 기록 (실패 로그 요약, 되돌린 커밋 해시)

5. 커밋: `ci: 타입체크, 테스트, 빌드 단계 추가`

## 학습 포인트
- 커버리지 게이트는 "숫자를 보고 있다"가 아니라 "미달이면 머지를 막는다"가 목적이다
- `pnpm build`는 타입 에러와 import 에러를 CI에서 한 번 더 잡는다
