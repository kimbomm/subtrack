# 10/31 (토) · 3주차 3일 — Branch protection과 PR 템플릿

**유형**: 구현 | **시간**: 2시간

## 오늘의 목표
main 브랜치를 보호해서 CI가 통과해야만 머지되도록 설정하고, PR 템플릿을 만든다.

## 사전 확인
- 저장소가 **public**인지 확인 (private 무료 플랜은 Branch protection이 제한될 수 있음)
- 워크플로우 job 이름이 `verify`인지 확인. 이 이름을 필수 체크로 지정한다

## 구현 (100분)

1. GitHub 저장소 → Settings → Branches → Add branch ruleset(또는 Branch protection rule)
   - Branch name pattern: `main`
   - [x] Require a pull request before merging
   - [x] Require status checks to pass before merging → `verify` 선택
   - [x] Require branches to be up to date before merging
   - [x] Do not allow bypassing the above settings (가능하면)

2. PR 템플릿 (`.github/pull_request_template.md`)
```md
## 변경 내용
-

## 변경 이유 / 관련 이슈
-

## 테스트 방법
- [ ] `pnpm test` 통과
- [ ] `pnpm e2e` 통과 (UI 변경 시)
- [ ] 수동 확인 내용:

## 체크리스트
- [ ] 커버리지 기준 유지
- [ ] 보안 영향 검토 (입력 검증, 헤더, 외부 데이터 출력)
- [ ] 접근성 영향 검토 (키보드, 라벨, 대비)
```

3. 검증 실험
   - 일부러 실패하는 테스트가 있는 브랜치에서 PR 생성
   - 머지 버튼이 비활성화되는지 확인하고 스크린샷 저장
   - 실험 브랜치는 PR을 닫고 삭제

4. 커밋: `docs: PR 템플릿 추가`

## 학습 포인트
- Branch protection은 "사람이 실수로 main에 직접 push하는 것"과 "실패한 PR이 머지되는 것"을 막는다
- 필수 체크 이름이 워크플로우 job 이름과 다르면 머지가 영원히 대기 상태가 된다. 이름을 정확히 맞춘다

## 완료 체크리스트
- [ ] main 브랜치 보호 규칙 설정
- [ ] 실패 PR 머지 차단 스크린샷 확보
- [ ] PR 템플릿 커밋
- [ ] 실험 브랜치 정리

## 막히면 확인할 것
- 상태 체크 목록에 `verify`가 안 보이면 워크플로우가 최소 한 번 실행되었는지 확인
- private 저장소에서 규칙이 적용되지 않으면 public 전환 또는 플랜 확인
