# 11/04 (수) · 3주차 7일 — CI에 E2E 추가

**유형**: 구현 | **시간**: 2시간

## 오늘의 목표
E2E를 CI에 포함하고, 브라우저 캐시와 실패 리포트 업로드를 설정한다. CI 실행 시간을 기록한다.

## 구현 (100분)

1. `ci.yml`에 E2E 잡 추가 (`verify` 잡과 분리)
```yaml
  e2e:
    runs-on: ubuntu-latest
    needs: verify
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Playwright 브라우저 캐시
        id: pw-cache
        uses: actions/cache@v4
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml') }}

      - name: Playwright 브라우저 설치
        if: steps.pw-cache.outputs.cache-hit != 'true'
        run: pnpm exec playwright install --with-deps chromium

      - run: pnpm e2e

      - name: 실패 리포트 업로드
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: playwright-report/
          retention-days: 7
```

2. 브랜치 보호의 필수 체크에 `e2e` 잡 추가 (Settings → Branches)

3. 의도적 실패 확인
   - E2E 테스트 하나를 일부러 틀리게 고쳐 push
   - Actions에서 실패 아티팩트가 생성되는지 확인
   - 원래대로 되돌림

4. CI 실행 시간 기록
   - `verify` 잡과 `e2e` 잡 각각의 소요 시간을 3회 측정해서 메모
   - 평균값을 README 수치 표에 적을 준비

5. 커밋: `ci: E2E 잡과 실패 리포트 업로드 추가`

## 학습 포인트
- `needs: verify`는 단위 검증이 실패하면 E2E를 돌리지 않아 비용과 시간을 아낀다
- 브라우저 캐시 키에 lockfile 해시를 넣어 Playwright 버전이 바뀌면 캐시가 새로 만들어지게 한다

## 막히면 확인할 것

- E2E가 CI에서만 실패하면 `webServer` 설정이 CI에서 `pnpm dev` 대신 빌드 후 실행을 쓰는지 확인 (4주차 11/07에 정리)
- 인메모리 데이터가 테스트 간에 섞이면 4주차 리셋 기능으로 해결 예정
