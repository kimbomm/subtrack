## 오늘의 목표
Vercel에 배포하고, 운영 환경에서 리셋 엔드포인트가 막혀 있는지 확인한 뒤 배포 URL을 확보한다.

## 구현 (100분)

1. Vercel 프로젝트 생성
   - Vercel 대시보드 → Add New → Project → GitHub 저장소 `subtrack` 선택
   - Framework Preset: Next.js (자동 감지)
   - Build Command, Output 기본값 유지

2. 환경 변수
   - 설정하지 않는 것이 원칙: `ALLOW_TEST_RESET`은 Production과 Preview 모두 비워 둔다
   - 필요한 변수가 있다면 `.env.example`과 대조해서 등록

3. 배포 확인 체크리스트
   - [ ] 메인 페이지 접속 및 목록 표시
   - [ ] 등록, 수정, 삭제 한 번씩 동작
   - [ ] `POST /api/test/reset` 호출 시 404 응답
   ```bash
   curl -i -X POST https://<배포주소>/api/test/reset
   ```
   - [ ] `curl -I https://<배포주소>`에서 보안 헤더 확인
   - [ ] 모바일 폭(약 375px)에서 레이아웃이 깨지지 않음

4. PR 프리뷰 확인: 11/04 이후 PR을 하나 열어서 Vercel 프리뷰 URL이 댓글로 달리는지 확인

5. README 상단에 배포 URL 추가 (내용은 11/10에 본격 작성)

6. 커밋: `docs: 배포 URL 추가` (또는 README 작성 전이면 생략 가능)

## 학습 포인트
