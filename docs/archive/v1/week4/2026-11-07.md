# 11/07 (토) · 4주차 3일 — E2E 확장과 테스트 데이터 리셋

**유형**: 구현 | **시간**: 2시간

## 오늘의 목표
E2E를 3~4개로 늘리고, 테스트마다 데이터가 깨끗하도록 테스트 전용 리셋을 만든다. 3회 연속 실행해서 flaky가 없는지 확인한다.

## 구현 (100분)

1. 테스트 전용 리셋 엔드포인트 (`src/app/api/test/reset/route.ts`)
```ts
import { NextResponse } from 'next/server';
import { subscriptionRepository } from '@/lib/subscriptions';

export async function POST() {
  if (process.env.NODE_ENV === 'production' || process.env.ALLOW_TEST_RESET !== 'true') {
    return NextResponse.json({ error: { code: 'NOT_FOUND' } }, { status: 404 });
  }
  for (const item of await subscriptionRepository.list()) {
    await subscriptionRepository.remove(item.id);
  }
  return NextResponse.json({ ok: true });
}
```
> 운영 배포에서는 `ALLOW_TEST_RESET`을 설정하지 않으므로 404가 된다. 이 설계가 "운영에 테스트 기능이 노출되지 않는다"는 근거다.

2. Playwright 설정에 환경 변수 추가 (`playwright.config.ts`의 `webServer`)
```ts
webServer: {
  command: 'pnpm dev',
  url: 'http://localhost:3000',
  reuseExistingServer: !process.env.CI,
  env: { ALLOW_TEST_RESET: 'true' },
},
```

3. 각 테스트 시작 전에 리셋 호출
```ts
import { test } from '@playwright/test';

test.beforeEach(async ({ request }) => {
  await request.post('/api/test/reset');
});
```

4. E2E 추가 (`e2e/subscription-edit-delete.spec.ts`, `e2e/subscription-filter.spec.ts`)
   - 수정: 등록 → 수정 버튼 → 금액 변경 → 목록에서 새 금액 확인
   - 삭제: 등록 → 삭제 → 목록에서 사라짐 확인
   - 필터: 월간·연간 두 개 등록 → 주기 필터 선택 → 한 개만 보임 → URL 쿼리 확인

5. 3회 연속 실행
```bash
pnpm exec playwright test --repeat-each=3
```

6. 커밋: `test: 수정·삭제·필터 E2E 추가와 테스트 데이터 리셋`

## 학습 포인트
- flaky 테스트의 흔한 원인: 테스트 간 데이터 공유, 고정된 대기 시간(`waitForTimeout`), 로딩 완료 전 조작
- 고정 대기 대신 `expect(...).toBeVisible()` 같은 자동 대기 assertion을 쓴다
