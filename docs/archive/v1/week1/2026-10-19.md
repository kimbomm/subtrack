# 10/19 (월) · 1주차 5일 — 반올림 정책과 입력 검증

**유형**: 구현 | **시간**: 2시간

## 오늘의 목표
반올림 정책을 코드로 고정하고, 잘못된 금액 입력은 명시적 에러로 처리한다.

## 정책 정의 (구현 전에 메모로 먼저 확정)

| 항목 | 정책 |
|---|---|
| 내부 계산 | 소수점 유지 |
| 최종 출력 | 원 단위 반올림 (`Math.round`) |
| 0원 | 허용 |
| 음수, NaN, Infinity | 거부 (`InvalidAmountError`) |

> 실무에서는 "계산 중간에는 반올림하지 않고, 표시·저장 시점에 한 번만 반올림한다"는 원칙을 많이 씁니다. 중간 반올림은 오차를 누적시키기 때문입니다.

## 구현 (80분)

1. 테스트 먼저 작성 (`src/domain/errors.test.ts`, `billing.test.ts`에 추가)
```ts
it('음수 금액은 InvalidAmountError를 던진다', () => {
  expect(() => toMonthlyCost({ amount: -1, cycle: 'monthly' }))
    .toThrow(InvalidAmountError);
});

it('NaN은 거부한다', () => {
  expect(() => toMonthlyCost({ amount: Number.NaN, cycle: 'monthly' }))
    .toThrow(InvalidAmountError);
});

it('Infinity는 거부한다', () => {
  expect(() => toMonthlyCost({ amount: Infinity, cycle: 'monthly' }))
    .toThrow(InvalidAmountError);
});
```

2. `src/domain/errors.ts`
```ts
export class InvalidAmountError extends Error {
  constructor(amount: number) {
    super(`유효하지 않은 금액입니다: ${amount}`);
    this.name = 'InvalidAmountError';
  }
}
```

3. 검증 함수와 반올림 함수 추가
```ts
export function assertValidAmount(amount: number): void {
  if (!Number.isFinite(amount) || amount < 0) {
    throw new InvalidAmountError(amount);
  }
}

export function roundWon(value: number): number {
  return Math.round(value);
}
```

4. `toMonthlyCost` 시작 부분에서 `assertValidAmount(sub.amount)` 호출

5. 반올림 테스트: `roundWon(4333.33)` → `4333`, `roundWon(4333.5)` → `4334`

6. 커밋: `feat: 금액 검증과 반올림 정책 추가`

## 학습 포인트
- `class ... extends Error`를 쓸 때 `this.name`을 지정하면 에러 로그에서 구분하기 쉽다
- `Number.isFinite`는 NaN과 Infinity를 모두 거른다 (`isNaN`은 문자열을 숫자로 바꾼 뒤 판단해서 혼동이 있다)
