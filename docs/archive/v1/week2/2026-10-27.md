# 10/27 (화) · 2주차 6일 — MSW로 API 모킹과 실패 상태 테스트

**유형**: 구현 | **시간**: 2시간

## 오늘의 목표
MSW로 API를 모킹하고, 제출 성공·실패·네트워크 에러·제출 중 상태를 테스트한다.

## 구현 (80분)

1. 패키지 설치
```bash
pnpm add -D msw
```

2. 핸들러 (`src/mocks/handlers.ts`)
```ts
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.post('http://localhost/api/subscriptions', async ({ request }) => {
    const body = await request.json();
    return HttpResponse.json({ id: 'mock-1', ...(body as object) }, { status: 201 });
  }),
];
```

3. 서버 설정 (`src/mocks/server.ts`)
```ts
import { setupServer } from 'msw/node';
import { handlers } from './handlers';

export const server = setupServer(...handlers);
```

4. `vitest.setup.ts`에 라이프사이클 추가
```ts
import { beforeAll, afterEach, afterAll } from 'vitest';
import { server } from './src/mocks/server';

beforeAll(() => server.listen({ onUnhandledRequest: 'error' }));
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
```

5. 폼 제출 로직에서 `fetch`를 쓰는 부분은 상위 컴포넌트나 `createSubscription` 함수로 분리하고, 테스트에서 MSW로 응답을 바꾼다
   > 주의: jsdom에서 `fetch('/api/...')` 상대 경로는 실패할 수 있으므로 절대 URL 또는 `window.location.origin` 기준으로 호출한다

6. 실패 케이스 테스트 (`SubscriptionForm.test.tsx`에 추가)
```tsx
import { http, HttpResponse, delay } from 'msw';
import { server } from '@/mocks/server';

it('서버가 500을 주면 에러 메시지를 보여준다', async () => {
  server.use(
    http.post('http://localhost/api/subscriptions', () =>
      HttpResponse.json({ error: { code: 'INTERNAL', message: '서버 오류' } }, { status: 500 }),
    ),
  );
  // 폼 입력 후 제출 → '저장에 실패했습니다' 메시지 확인
});

it('네트워크 에러 시 에러 메시지를 보여준다', async () => {
  server.use(http.post('http://localhost/api/subscriptions', () => HttpResponse.error()));
  // 제출 → 에러 메시지 확인
});

it('제출 중에는 버튼이 비활성화된다', async () => {
  server.use(
    http.post('http://localhost/api/subscriptions', async () => {
      await delay(300);
      return HttpResponse.json({ id: 'x' }, { status: 201 });
    }),
  );
  // 제출 직후 button이 disabled인지 확인 → 응답 후 다시 enabled인지 확인
});
```

7. 폼에 실패 메시지 표시 상태를 추가한 뒤(예: `submitError` state) 위 테스트가 통과하는지 확인

8. 커밋: `test: MSW 기반 제출 실패와 로딩 상태 테스트 추가`

## 학습 포인트
- `onUnhandledRequest: 'error'`는 테스트에서 실수로 실제 네트워크로 나가는 요청을 잡아준다
- `server.use`로 테스트별 응답을 바꾸고, `afterEach`의 `resetHandlers`로 되돌린다
- MSW는 실제 네트워크 계층을 가로채므로, 컴포넌트가 `fetch`를 어떻게 호출하는지 함께 검증할 수 있다

## 막히면 확인할 것
- `Failed to parse URL`: 상대 경로 문제. 절대 URL 사용
- 핸들러가 적용되지 않으면 `server.listen`이 `beforeAll`에서 실행되는지 확인
- `onUnhandledRequest` 에러가 나면 핸들러의 URL이 실제 요청 URL과 같은지 확인
