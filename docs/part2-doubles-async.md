# Part 2 — 테스트 더블과 비동기 (L07 ~ L08)

React로 넘어가기 전에, 의존성을 가짜로 바꾸는 법과 비동기 코드를 테스트하는 법을 순수 TS 코드로 먼저 익힌다.

---

## L07 테스트 더블: stub, spy, mock, fake

**목표**: 가짜 객체의 종류를 구분하고, 언제 모킹하지 말아야 하는지 판단할 수 있다.

**이론 핵심**
- stub: 정해진 값을 돌려줌 / spy: 호출 기록 / mock: 호출 기대를 검증 / fake: 진짜처럼 동작하는 간단한 구현 (예: 인메모리 저장소)
- Vitest: `vi.fn()`, `vi.spyOn()`, `vi.mock()`, `mockResolvedValue`, `toHaveBeenCalledWith`
- 모킹이 많을수록 테스트가 구현에 묶인다. 경계(네트워크, 저장소, 시간)만 바꾸고 내 코드는 진짜로 돌린다.
- 인터페이스로 분리하면 `vi.mock` 없이 fake를 넣을 수 있다.

**예측 질문 예시**
- `vi.mock('./repo')`로 저장소를 전부 가짜로 만들고 "저장 함수가 호출되었다"만 확인하면, 어떤 버그를 놓칠 수 있을까?

**실습**
1. [레드 통과] Claude가 `SubscriptionRepository` 인터페이스와 `SubscriptionService`(추가, 목록, 월 합계)의 실패하는 테스트를 준다. 학습자는 인메모리 fake 저장소와 서비스를 구현한다.
   - 위치 예시: `src/lib/subscriptions/`
2. [리뷰] Claude가 같은 기능을 `vi.mock` 범벅으로 테스트한 버전을 보여준다. 리팩터링(예: 함수 이름 변경)을 하면 어느 쪽이 깨지는지 예측하고 직접 확인한다.

**통과 기준**
- 서비스 테스트에 `vi.mock`이 없다
- fake와 mock 버전의 차이를 한 문장으로 설명할 수 있다

**면접 질문**: "모킹은 언제 하고 언제 피하나요?"

## L08 비동기와 타이머

**목표**: Promise, 에러, 디바운스 같은 시간 기반 코드를 안정적으로 테스트한다.

**이론 핵심**
- `await expect(p).resolves` / `rejects.toThrow()` — `await`를 빼먹으면 테스트가 항상 통과할 수 있다.
- 가짜 타이머: `vi.useFakeTimers()`, `vi.advanceTimersByTime()`, `vi.runAllTimersAsync()`
- 마이크로태스크와 타이머의 실행 순서 (v1 10/18 기본기 내용과 연결)

**예측 질문 예시**
- `expect(fetchSomething()).rejects.toThrow()` 앞에 `await`가 없으면 어떻게 될까?

**실습**
1. [버그 잡기] Claude가 `await`가 빠져서 항상 통과하는 테스트를 준다. 학습자는 이 테스트가 거짓으로 통과한다는 것을 증명(구현을 깨뜨려도 통과)하고 고친다.
2. [TDD] `debounce(fn, ms)`를 테스트부터 작성해 구현한다 (나중에 검색 입력에서 사용). 마지막 호출만 실행됨, 시간이 지나기 전엔 실행 안 됨, 인자 전달.
3. [TDD] `retry(asyncFn, times)` — 실패하면 다시 시도하고 끝내 실패하면 마지막 에러를 던진다.

**통과 기준**
- 모든 비동기 테스트가 실제 시간을 기다리지 않는다 (전체 테스트 1초 이내)
- 돌연변이 검사: 디바운스의 `clearTimeout` 제거를 잡아낸다
