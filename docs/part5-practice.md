# Part 5 — 실무 적용 (L20 ~ L21)

실무 코드는 대부분 테스트 없이 시작된다. 이미 있는 코드에 테스트를 붙이는 법과, 팀에 테스트를 도입하는 이야기를 정리한다.

---

## L20 레거시 코드에 테스트 붙이기

**목표**: 테스트가 없는 지저분한 컴포넌트를 안전하게 리팩터링한다.

**이론 핵심**
- 특성 테스트(characterization test): "올바른 동작"이 아니라 "지금의 동작"을 먼저 고정한다
- 이음새(seam) 찾기: 의존성을 바꿀 수 있는 지점 (props, 모듈 경계, 네트워크)
- 순서: 바깥에서 테스트로 감싸기 → 작은 리팩터링 → 로직을 순수 함수로 빼기 → 단위 테스트로 내리기
- 팀 도입 전략: 새 코드부터, 버그 수정 시 재현 테스트부터, 커버리지 강제보다 핵심 흐름부터

**실습**
1. [테스트 리팩터] Claude가 300줄짜리 컴포넌트를 준다 (fetch, 계산, 날짜 처리, 필터가 한 파일에 섞여 있고 버그 1개 포함). 학습자는
   - 먼저 특성 테스트로 현재 동작을 고정하고
   - 로직을 빼내 단위 테스트로 옮기고
   - 숨은 버그를 발견하면 재현 테스트를 먼저 쓰고 고친다
2. 리팩터링 전후의 테스트 수와 구조를 비교해 정리한다.

**통과 기준**
- 리팩터링 중 특성 테스트가 계속 초록
- 숨은 버그를 재현 테스트와 함께 고침

**면접 질문**: "테스트가 없는 프로젝트에 테스트를 도입한다면 어디서부터 시작하겠어요?"

## L21 테스트 전략 정리와 면접

**목표**: 지금까지 한 것을 남에게 설명할 수 있는 형태로 정리한다.

**실습**
1. README에 테스트 전략 섹션 작성: 층별 도구, 무엇을 어디서 테스트하는지, 실행 방법, 수치(테스트 수, 커버리지, CI 시간).
2. [리뷰] Claude가 면접관 역할로 10문항 모의 면접을 진행한다. 각 Part의 면접 질문 + 꼬리 질문. 답변마다 피드백.
3. PROGRESS.md의 "회사에서는 이렇게 적용하겠다" 메모를 모아서 실무 적용 계획 1쪽으로 정리한다.

**통과 기준**
- README만 읽고 다른 사람이 테스트를 실행하고 전략을 이해할 수 있다
- 모의 면접 10문항 완료
