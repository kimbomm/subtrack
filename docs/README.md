# SubTrack 테스트 커리큘럼 v2

프론트엔드 개발자가 **실무에서 바로 쓸 수 있는 테스트 감각**을 익히는 과정이다.
구독 관리 앱 SubTrack을 만들면서 단위 테스트 → TDD → 컴포넌트 테스트 → E2E → CI 순서로 올라간다.

## v1과 무엇이 다른가

| | v1 (날짜 기반) | v2 (수업 기반) |
|---|---|---|
| 단위 | 날짜별 할 일 | 수업(Lesson)별 목표와 통과 기준 |
| 코드 | 테스트와 정답 구현을 문서에 같이 제공 | 정답 없음. 요구사항과 통과 조건만 있고 학습자가 직접 작성 |
| 확인 | 체크리스트를 스스로 체크 | Claude가 실행해서 채점하고, 테스트를 일부러 깨뜨려 품질까지 확인 |
| 밀릴 때 | 일정 전체를 다시 조정 | 진행 상황 파일에서 이어서 시작 |
| 범위 | 테스트 + CSP·배포 등 포트폴리오 항목 | 테스트에 집중. 보안·배포는 보류 |

## 수업 진행 방식

```
이론(짧게) → 예측 질문 → 문제 출제 → 직접 풀이 → 채점 → (힌트) → 설명·면접 질문 → 다음 수업
```

Claude에게 하는 말:

| 말 | Claude가 하는 일 |
|---|---|
| `수업 시작` / `다음 수업` | PROGRESS.md를 읽고 현재 수업을 이어서 진행 |
| `채점해줘` | 테스트 실행, diff 확인, 돌연변이 검사 후 결과 알려주기 |
| `힌트` | 힌트를 한 단계 올려서 주기 (방향 → 개념 → 부분 코드) |
| `정답` | 정답 공개 (PROGRESS.md에 기록됨) |
| `설명해줘` | 막힌 개념만 다시 설명 (코드 정답은 주지 않음) |

자세한 규칙은 루트의 [CLAUDE.md](../CLAUDE.md)에 있다. Claude Code는 이 파일을 세션마다 자동으로 읽는다.

## 공통 규칙

- 도메인 로직은 테스트를 먼저 쓴다. 가능하면 `test:` 커밋과 `feat:` 커밋을 나눈다.
- 커밋은 학습자가 직접 한다. 접두어: `feat:`, `test:`, `refactor:`, `fix:`, `chore:`, `ci:`, `docs:`
- 회사 코드·데이터는 넣지 않는다. 각 Part 끝에 "회사에서는 이렇게 적용하겠다" 메모만 남긴다.
- 보류 항목: CSP·보안 헤더, Vercel 배포, Storybook, 시각적 회귀 테스트, Lighthouse CI. 전체를 마친 뒤 여유가 있으면 진행한다.
